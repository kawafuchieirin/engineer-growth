# ゲーム要素の設計仕様

この文書は XP・レベル・実績・クエストの**計算規則の正**である。
実装（`src/lib/xp.ts` ほか）はこの規則に従い、変更するときは先にここを直す。

## 大原則: 盛れない仕組みにする

XP は `data/` と `blog/` から機械的に導出するだけで、**XP を直接書く場所を作らない**。
XP を増やす唯一の方法は、実際にスキルを上げる・KR を進める・記事を書くことである。

この制約がないと、落ち込んだ日に数字をいじって気分を良くする道具になり、
「成長している」という感覚だけが残って成長が止まる。`data/skills.yaml` が
レベル 3 以上に根拠（`evidence`）を要求しているのも同じ理由。

カテゴリの `weight` は XP に**掛けない**。weight は自分で決められる値なので、
掛けるとスライダーを動かすだけで XP が増えてしまう。weight はレーダーチャートと
重み付き平均（どこに注力しているかの表現）だけに使う。

## XP の計算

### スキル（`skills`）

レベルごとの**累積** XP。上の段ほど重くすることで、「3 から 4」の価値が
「0 から 1」より大きいという実感に合わせる。

| レベル | 累積 XP |
|---|---|
| 0 | 0 |
| 1 | 10 |
| 2 | 30 |
| 3 | 70 |
| 4 | 150 |
| 5 | 300 |

スキル XP = 全スキルの累積 XP の合計。

### 目標（`goals`）

- Key Result 1 件につき `20 × min(current / target, 1)` XP
- `status: done` の目標に完了ボーナス 100 XP
- `status: dropped` は完了ボーナスなし。ただし KR の進捗 XP は残す
  （取りやめた目標でも、そこまでに動いた分の労力は実在するため）

### ロードマップ（`roadmap`）

- 完了したステップ 1 つにつき 15 XP
- `status: done` のマイルストーンに完了ボーナス 80 XP

### ブログ（`blog`）

- 公開記事 1 本につき 50 XP
- 下書きは 0 XP（書き上げて出すまでが 1 本）

### 実績（`achievements`）

解放済み実績の `xp` の合計。

## プレイヤーレベル

累積 XP からレベルを決める。必要累計 XP は次の式。

```
xpForLevel(n) = round(80 * n ** 1.5)      // n >= 1、xpForLevel(0) = 0
```

| レベル | 必要累計 XP |
|---|---|
| 1 | 80 |
| 2 | 226 |
| 3 | 416 |
| 5 | 894 |
| 10 | 2530 |
| 20 | 7155 |

上限は設けない。指数ではなく 1.5 乗にしているのは、後半で「何をしても上がらない」
状態にしないため。伸びが鈍るのは実態に合っているが、止まると続かない。

## ストリーク

- **連続投稿週数**: 記事の公開日を週（月曜始まり）に丸め、基準日の週から
  過去に向かって連続している週数。基準日の週にまだ記事がない場合は、
  前週までの連続数を保ったまま「今週が未達」として `atRisk` に入れる
  （書けば途切れないので、まだ間に合うことを伝える）
- **連続投稿月数**: 同じ考え方を月単位で
- **連続棚卸し四半期数**: `owner.updated` が各四半期に 1 回以上更新されている連続数。
  履歴（`data/history.yaml`）の `date` から判定する

## 成長の差分

「伸びた」を見せるための中核。`data/history.yaml` のスナップショットと現在値を比較する。

- **前回の記録から**: 直近のスナップショットとの差
- **直近 90 日**: 90 日前に最も近いスナップショットとの差
- **始めてから**: 最初のスナップショットとの差

履歴が足りない場合は、その差分を出さずに「記録を積むと差分が見られる」ことを伝える。
嘘の 0 を見せない。

## クエスト

次の一手を最大 5 件提示する。順序は `urgency`（`now` → `soon` → `later`）、
同じ緊急度なら XP の降順。各クエストは次を必ず持つ。

- **何をするか**（命令形）
- **なぜ今か**（納得できない指示は無視されるため必須）
- **増える XP の見込み**
- **編集するファイル**（迷いをなくす）

種別は、期限が近い／遅れているマイルストーンのステップ、進捗の遅い KR、
ギャップの大きいスキル、途切れそうなストリーク、データ品質の警告（根拠の欠落、
最終利用が古い）から作る。

## この仕組みが壊れるとき

- **XP が増えることが目的になったとき**。クエストに「なぜ」を必須にしているのは
  このため。納得できないクエストはやらなくてよい
- **実績の条件が実力と無関係になったとき**。「記事を 100 本書いた」は実績になるが、
  「ログインした」は実績にならない。何かを**成した**ことだけを実績にする
