# スキル可視化ガイド

`data/skills.yaml` を使ったスキル棚卸しの運用手順。
このファイルは「どう書くか」を決める規約で、データ自体は `data/skills.yaml`、
レベルの定義は `data/levels.yaml` が単一の信頼できる情報源である。

> **最初にやること**: `data/skills.yaml` はシードデータ（サンプル値）が入った状態です。
> `owner.name` の `<あなたの名前>` と、各スキルの `level` / `target` /
> `experience_years` / `last_used` / `evidence` を自分の実態に書き換えてください。
> スキルの `id` は目標・ロードマップ・ブログから参照されるため、
> **既存 ID の改名・削除は参照整合性エラーになります**（追加は自由）。

> **キーのタイポはエラーになります**: スキーマは未知のキーを拒否します。
> `taget:`（`target` の書き間違い）のような 1 文字違いが「目標未設定＝現状維持」として
> 黙って無視されるのを防ぐためです。`pnpm validate` が `Unrecognized key(s) in object`
> を出したら、そのキー名の綴りを見直してください。

## 1. レベル 0-5 の使い分け

定義の正は `data/levels.yaml`。判断に迷ったときの目安を添える。

| レベル | 呼称 | 判断の目安（これが言えるか） |
|---|---|---|
| 0 | 未経験 | 名前と用途は知っているが触っていない。 |
| 1 | 入門 | チュートリアルを動かした。実務では必ず誰かの助けが要る。 |
| 2 | 補助付き実務 | 実務タスクを完了できるが、設計判断とレビューは他者に依存する。 |
| 3 | 自走 | 設計から実装・運用まで一人で完遂し、典型的な障害に対処できる。 |
| 4 | 牽引 | 技術選定を主導し、他者をレビュー・育成できる。非自明な問題を解ける。 |
| 5 | 第一人者 | 組織横断で基準を作り、社外発信や継続的貢献で認知されている。 |

判定のコツ:

- **「できる」ではなく「やった」で決める。** 読んで理解できる状態はレベル 1-2 止まり。
- **境界は 2 と 3。** 「レビューされる前提か / されなくても出荷できるか」で切る。
- **4 以上は他者への影響が条件。** 自分が速いだけならレベル 3。
- 迷ったら低い方を選ぶ。低く付けてギャップとして可視化した方が、次の行動につながる。

## 2. 自己評価の付け方（evidence 必須の考え方）

レベルは主張であり、`evidence` はその根拠である。根拠を書けないレベルは付けない。

- **レベル 3 以上は `evidence` を 1 件以上書く。** 書かれていない場合は
  `warnings` に「evidence が未記入」として出力され、サイトと `skills-report` に表示される
  （ビルドは失敗しない。記入途中でも生成できるようにするため）。
- evidence は**行為と結果**で書く。主観の形容詞は根拠にならない。
  - ✅ `マルチステージビルドでイメージサイズを 70% 削減`
  - ✅ `本番環境の IaC をモジュール分割して単独で設計・運用`
  - ❌ `得意`／`かなり理解している`
- 公開できる成果物があれば `links`（`label` + `url`）に残す。設計ドキュメント・PR・記事・登壇資料など。
- 自信のなさ・未経験の領域は `notes` に書く。「何ができないか」が次の目標の種になる。
- `last_used`（`YYYY-MM`）は正直に書く。`owner.updated` から **12 ヶ月以上前**だと
  「レベルが実態と合っているか」の warning が出る。鈍った技術を過大評価しないための仕組み。
  基準をビルド日ではなく `owner.updated` にしているのは、データを変えていないのに
  生成物の warning が増減しないようにするため（出力を決定的に保つ）。
- その代わり、`owner.updated` 自体が **6 ヶ月以上前**（四半期棚卸しを 2 回飛ばした状態）だと
  「棚卸し日が古い」warning が出る。基準日が腐ると上の判定も効かなくなるため。

## 3. weight（カテゴリの重み）の決め方

`categories[].weight` は **0.1-2.0** の数値で、「自分のキャリアにおける重要度」を表す。
レーダーチャートの軸と、`stats.weightedAverageLevel`（重み付き平均）に使われる。

| weight | 位置づけ |
|---|---|
| 1.5 - 2.0 | 看板にしたい中核領域。ここのレベルが自分の市場価値になる。 |
| 1.0 - 1.4 | 日常業務で常用する領域。落とせない。 |
| 0.5 - 0.9 | 隣接領域。会話が成立すれば十分。 |
| 0.1 - 0.4 | 当面は投資しないと決めた領域。 |

決め方の原則:

- **合計を 1 や 100 に揃える必要はない。** 相対的な比だけが意味を持つ。
- **「今やっていること」ではなく「これからなりたい姿」で決める。**
  weight は目標の宣言であり、平均レベルを良く見せるための調整値ではない。
- 重み付き平均は各スキルに所属カテゴリの weight を掛けて平均する。
  そのため**全カテゴリの weight が等しいとき、単純平均と一致する**（検算に使える）。
  単純平均との差が、重点領域に注力できているかの指標になる。
- weight を変えるのはキャリアの方針を変えるときだけ。四半期ごとに動かすものではない。

## 4. 四半期ごとの棚卸し手順

30-60 分で終わるように手順を固定する。

1. **現状確認** — `pnpm growth skills-report` を実行し、前回からの変化と warning を確認する。
2. **レベルの見直し** — この 3 ヶ月で実際にやったことを根拠に `level` を更新する。
   - 上げる場合は `evidence` を必ず 1 件追加する（根拠なしの昇格は禁止）。
   - 使わなくなった技術は**下げてよい**。`last_used` を更新し、必要なら `notes` に理由を書く。
3. **warning の解消** — evidence 未記入・最終利用が古い項目を潰す。
   直せないもの（実際に 1 年触っていない等）は、レベルを下げるのが正しい対処。
4. **target の更新** — 次の 3-6 ヶ月で手が届く目標に置き直す。
   - 一度に `+1` 以上のギャップを 3-5 件に絞る。全部に高い目標を置くと優先順位が消える。
   - 既に達成した target は引き上げるか、現状維持なら `target` を外す（`target` 未設定 = 現状維持）。
   - `level > target`（目標超過）はエラーではない。実態をそのまま記録してよい。
     集計では「目標は現在を下回らない」と解釈するため（カテゴリの目標平均は `level` で下支えされる）、
     レーダーチャートの目標ポリゴンが現在ポリゴンの内側に入ることはない。
5. **新規スキルの追加** — 触り始めたものを `level: 1` で登録する。ID は kebab-case・全体で一意。
6. **棚卸し日の更新** — `owner.updated` を当日の日付（`YYYY-MM-DD`）にする。
   warning の「12 ヶ月以上前」判定はこの日付が基準なので、更新を忘れると判定がずれる。
7. **検証と反映** — `pnpm validate` → `pnpm build` を実行し、生成物を確認してコミットする。

棚卸しの出力（ギャップ上位）は、そのまま次の四半期の目標（`data/goals.yaml`）の入力になる。

## 5. `pnpm growth skills-report` の使い方

ターミナルでスキル棚卸しのサマリを確認するコマンド。`data/skills.yaml` の検証も同時に走る。

```bash
# 全カテゴリのサマリ + ギャップ + データ品質の注意
pnpm growth skills-report

# カテゴリで絞り込む（id は languages / backend / frontend / infra / cloud / data / practice / soft）
pnpm growth skills-report --category infra
pnpm growth skills-report --category=soft

# 目標とのギャップだけを見る（次の一手を決めるとき）
pnpm growth skills-report --gaps

# 絞り込みとの併用も可能
pnpm growth skills-report --category backend --gaps

# ヘルプ
pnpm growth skills-report --help
```

出力の読み方:

- 1-2 行目がサマリ（スキル数 / 平均 / 重み付き平均 / レベル4以上の数）。
- カテゴリごとに `████·` のバーで現在レベル、括弧内が目標。
- 「次に伸ばすスキル」は `target - level` の降順。同じギャップなら現在レベルが低い順
  （着手の費用対効果が高い順）に並ぶ。ここの上位が次の四半期の候補。
- 最後の「データ品質の注意」は棚卸しの宿題。絞り込み表示でも必ず全件表示される。

## 6. 関連コマンドと生成物

| コマンド | 内容 |
|---|---|
| `pnpm growth skills-report` | ターミナルにサマリを表示（上記） |
| `pnpm validate` | 全データのスキーマ・参照整合性検証 |
| `pnpm build` | `dist/skills.html`（レーダーチャート付き）と `PROFILE.md` を生成 |
| `pnpm test` | 集計ロジック・スキーマ・レンダラのテスト |

`dist/` と `PROFILE.md` は生成物なので手で編集しない。直すのは常に `data/skills.yaml` 側。
