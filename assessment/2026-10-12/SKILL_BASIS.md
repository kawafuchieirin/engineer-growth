# スキルごとの判定根拠（2026-10-12）

`data/skills.yaml` の各レベルを、どの測定値で決めたかの対応表。
数字の出どころは [`raw/`](./raw/)、測り方は [`measure.sh`](./measure.sh)。

レベルの定義は `data/levels.yaml`（0 未経験 / 1 入門 / 2 補助付き実務 /
3 自走 / 4 牽引 / 5 第一人者）。

**4 以上が 1 件も無いのは測定の結果である。** レベル 4 は「技術選定を主導し、
他者をレビュー・育成できる」で、その証跡は単独開発のリポジトリには原理的に残らない。
測れなかったものを「無い」と書くのは不正確なので、`要確認` として残した。

### infra-network — ネットワーク → **2**（初版の 1 から訂正）

| 根拠 | 測定値 |
|---|---|
| Terraform での VPC 定義（HEAD） | 0 件 |
| **CloudFormation での VPC 定義（git 履歴）** | **VPC 4 / Subnet 4 / RouteTable 4 / InternetGateway 4 / SecurityGroup 7 ファイル** |
| ALB / RDS / EC2（git 履歴） | ALB 3 / RDS 3 / EC2 4 ファイル |
| ANS-C01 の学習成果物 | サービス別ノート、クイズ TUI（aws-exam の履歴） |

**初版で「構築が 0 件」としたのは測定の誤りだった。**
`RaiseTech_kadaiyou_repo`（2023-03〜07、71 コミット）に、マルチ AZ の VPC
（Public/Private サブネット各 2・ルートテーブル 2・IGW・SG）を CloudFormation で
構築した実物が残っている。CIDR をパラメータ化し、アベイラビリティゾーンを
`!Select` で取得してハードコードを避けている。

見落とした原因は 3 つ（`history.sh` を新設して再現可能にした）。

1. 対象の誤り — 言語 API が `{}` を返し HEAD も空に見えたため、リポジトリごと除外した
2. パターンの誤り — `.tf` の `aws_vpc` だけを検索した。CloudFormation は `.yml` の `AWS::EC2::VPC`
3. HEAD のみ検索 — ファイルは後のコミットで削除され、git 履歴にしか残っていない

**3 に留めた理由**: スクールの課題として手本に沿って作ったものであり、
設計を自分で起こした経験と運用の経験が無い。かつ **last_used が 2023-07 で 39 ヶ月前**
（`validate` が警告を出す）。M2「手本つきで作った」に該当する。
